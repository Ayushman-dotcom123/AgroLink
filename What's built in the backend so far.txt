Backend concepts — learn through this project
Here's how the backend works, explained through AgroLink's actual code:

1. What is a backend?

The frontend (React) runs in the user's browser. It can't directly touch a database — that would be a security disaster. The backend is a middleman server that:

Receives requests from the frontend
Validates them
Talks to the database
Returns data
Browser (React) → HTTP Request → Express Server → MySQL → Response → Browser
2. Express.js — the web framework

server.js is the entry point. Think of it like a traffic controller:

app.use('/api/auth', require('./routes/auth'))   // all /api/auth/* goes here
app.use('/api/crops', require('./routes/crops')) // all /api/crops/* goes here
Each route file handles one "domain" of your app.

3. Routes — what they are

A route is a URL + HTTP method + handler function:

// GET /api/crops — fetch all crops
router.get('/', auth, async (req, res) => {
  const [crops] = await db.query('SELECT * FROM crops WHERE is_available = 1')
  res.json(crops)
})

// POST /api/crops — create a crop listing
router.post('/', auth, async (req, res) => {
  const { name, price_per_kg, quantity_kg } = req.body
  await db.query('INSERT INTO crops (name, price_per_kg, ...) VALUES (?, ?, ...)', [name, price_per_kg, ...])
  res.status(201).json({ success: true })
})
4. Middleware — runs before your route handler

auth.js middleware verifies the JWT token. Any route with auth as second argument requires login:

router.get('/me', auth, async (req, res) => {
  // req.user is set by the auth middleware
  res.json(req.user)
})
Without auth, the route is public (like the marketplace listing).

5. The request/response cycle

1. Frontend sends: POST /api/auth/login { email, password }
2. Express receives it
3. auth.js route handler runs
4. Queries MySQL: SELECT * FROM users WHERE email = ?
5. bcrypt compares password hash
6. If valid: creates JWT token
7. Returns: { token, user }
8. Frontend stores token in Zustand
9. Every future request sends: Authorization: Bearer <token>
10. auth middleware verifies token on protected routes
6. Environment variables (.env)

Never hardcode secrets. .env keeps them out of your code:

JWT_SECRET=...        ← signs/verifies tokens
DB_PASSWORD=...       ← database password
OPENWEATHER_API_KEY=  ← third-party API
process.env.JWT_SECRET reads them in code.

7. The database layer

db.js
 creates a connection pool — a set of reusable database connections so you don't open/close one per request:

const pool = mysql.createPool({ host, user, password, database })
// Usage anywhere:
const [rows] = await db.query('SELECT * FROM users WHERE email = ?', [email])
The ? placeholders prevent SQL injection — never concatenate user input directly into queries.
